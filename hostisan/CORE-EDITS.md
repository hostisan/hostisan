# Allowed core edits

Hostisan keeps Hestia's core (`bin/`, `func/`, `install/`, `src/`, `web/`) byte-identical to the upstream fork point `94c1e760f` (HestiaCP 1.10.5 + 65 commits), except for the files listed under **Allowed edits** below.

`tools/check-core-edits.sh` (`make core-edits-check`, run in CI) enforces this:

- a core file that differs from `94c1e760f` in `HEAD` and is not in the Allowed table fails with `unlisted core edit: <path>`;
- an Allowed row whose file does not differ fails with `stale entry: <path>`;
- the **Planned edits** table allows nothing. A task that makes a planned edit moves its row (or rows) into the Allowed table in the same commit.

Each row is one path, relative to the repository root. Added and deleted files count as edits. The check needs full git history (`fetch-depth: 0`) so the fork point exists.

Kinds: **security** (closes a security MUST), **function** (behaviour Hostisan needs), **branding** (text or images that never pass through the panel's brand map), **packaging** (debs, units, installer).
